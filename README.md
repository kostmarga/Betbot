Η σελίδα ανανεώνεται αυτόματα το πρωί (από ~06:07, με 3 προσπάθειες) και το απόγευμα (2 προσπάθειες) ώρα Ελλάδας. Το GitHub μπορεί να καθυστερήσει τα προγραμματισμένα τρεξίματα· αν η ώρα ενημέρωσης στη σελίδα είναι παλιά, άνοιξε το τελευταίο link → **Run workflow**.

Προσωπικό bot που **κάθε μέρα** μαζεύει δεδομένα για ποδόσφαιρο και μπάσκετ, υπολογίζει πιθανότητες
με στατιστικά μοντέλα και βγάζει **μία σελίδα με καρτέλες** (dashboards):

| Καρτέλα | Τι δείχνει |
|---|---|
| ⭐ Προτεινόμενο | Το δελτίο που προτείνεται να παίξεις (2–3 επιλογές, ~1.8–3.2) + ένα μονό |
| 🛡️ Safe | Οι 10 πιο σίγουρες επιλογές της ημέρας (μονά) |
| 🎯 10+ / 🔥 30+ / 🎰 100+ | Δελτία στα αντίστοιχα εύρη απόδοσης |
| ⚽ Over | Μόνο Over γκολ / Goal-Goal (λίστα + δελτίο) |
| 🚩 Κόρνερ · 🟨 Κάρτες · ↔️ Πλάγια | Over/Under κόρνερ, καρτών, πλαγίων άουτ (+ «ποιος κάνει περισσότερα κόρνερ») |
| 👤 Παίκτες | Σουτ, σουτ στην εστία, φάουλ, κάρτα, σκόρερ ανά παίκτη |
| 🔀 Συνδυαστικό | Δελτίο από διαφορετικές αγορές |
| 📉 Κινήσεις | Ποιες αποδόσεις **πέφτουν** (μπαίνουν λεφτά) και ποιες **ανεβαίνουν** |
| 📊 Ιστορικό | Πώς πάει **κάθε λίστα** (κέρδη/ζημιές, % επιτυχίας) |
| ⚙️ Πηγές | Αν δούλεψε κάθε πηγή σήμερα + οι κανόνες που εφαρμόζονται |

Κάθε επιλογή έχει **«Γιατί;»**: φόρμα, μέσοι όροι, πόσα από τα τελευταία ματς έβγαλαν την επιλογή,
H2H, απουσίες, διαιτητής, κίνηση απόδοσης.

> ⚠️ Στατιστική εκτίμηση, όχι εγγύηση. Ακόμα και οι «σίγουρες» επιλογές χάνουν ~1 στις 3–4.
> Το ταμείο της εβδομάδας (10€) και οι κανόνες του φαίνονται στην καρτέλα ⭐.

## ⏰ Αξιόπιστο ρολόι (το GitHub χάνει προγραμματισμένα τρεξίματα)

Τα `schedule` του GitHub Actions καθυστερούν ή χάνονται. Λύση: ένα **δωρεάν εξωτερικό ρολόι** που κάθε 10 λεπτά «πατά το κουμπί» του live workflow
(το οποίο ξεκινά μόνο του το daily όταν η σελίδα είναι ξεπερασμένη ή υπάρχουν αποτελέσματα που περιμένουν).

1. **Token (μία φορά):** GitHub → Settings → Developer settings → Personal access tokens → *Fine-grained tokens* → Generate.
   Repository access: *Only select repositories* → `Betbot`. Permissions → Repository → **Actions: Read and write** (τίποτα άλλο). Λήξη: 1 χρόνο. Αντίγραψε το token.
   ⚠️ Μην το γράψεις ΠΟΥΘΕΝΑ εκτός από το επόμενο βήμα (ούτε σε αρχεία του repo, ούτε στη συνομιλία· το repo είναι public).
2. **cron-job.org** (δωρεάν λογαριασμός) → *Create cronjob*:
   - URL: `https://api.github.com/repos/kostmarga/Betbot/actions/workflows/live.yml/dispatches`
   - Schedule: κάθε 10 λεπτά
   - Advanced → Request method: **POST** · Request body: `{"ref":"main"}`
   - Headers: `Authorization: Bearer <το token>` · `Accept: application/vnd.github+json` · `X-GitHub-Api-Version: 2022-11-28` · `Content-Type: application/json`
3. Έλεγχος: το cron-job.org πρέπει να δείχνει status **204**. Στο GitHub → Actions → «BetBot live» εμφανίζεται νέο τρέξιμο κάθε ~10'.

Αν το token λήξει ή ακυρωθεί, το cron-job.org δείχνει 401/403· τα προγραμματισμένα του GitHub συνεχίζουν ως εφεδρεία.

## 2. Εγκατάσταση (μία φορά, ~20 λεπτά)

Όλα είναι **δωρεάν**. Χρειάζονται: λογαριασμός GitHub, κλειδί The Odds API, (προαιρετικά) Gmail App Password.

### 2.1 GitHub
1. Φτιάξε λογαριασμό στο https://github.com (αν δεν έχεις).
2. **New repository** → όνομα π.χ. `betbot` → **Private** → Create.
3. Ανέβασε όλα τα αρχεία του φακέλου (κουμπί *Add file → Upload files*, ή με `git push`).
   Μην ξεχάσεις τον φάκελο `.github/` (είναι «κρυφός» στα Windows – ενεργοποίησε «Εμφάνιση κρυφών»).

### 2.2 The Odds API (αποδόσεις κυπέλλων Ευρώπης, NBA, Euroleague)
1. https://the-odds-api.com → *Get API key* → δωρεάν πακέτο (500 credits/μήνα).
2. Έρχεται email με το κλειδί.
3. GitHub → repo → **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `ODDS_API_KEY` · Secret: το κλειδί.

Το bot μοιράζει μόνο του τα credits ώστε να φτάνουν όλο τον μήνα (βλ. `config.yaml → collectors.odds_api`).

### 2.3 Email κάθε πρωί (προαιρετικό)
1. Gmail → Λογαριασμός Google → Ασφάλεια → **Επαλήθευση σε 2 βήματα** (πρέπει να είναι ενεργή).
2. Ψάξε «**Κωδικοί πρόσβασης εφαρμογών**» (App passwords) → φτιάξε έναν με όνομα `betbot` → 16 χαρακτήρες.
3. Πρόσθεσε 3 secrets στο GitHub: `SMTP_USER` (το gmail σου), `SMTP_PASS` (οι 16 χαρακτήρες), `MAIL_TO` (πού να έρχεται).
4. Στο `config.yaml` βάλε `email: enabled: true`.

Το email έχει σύνοψη + **συνημμένη όλη τη σελίδα** (άνοιξέ τη με διπλό κλικ).

### 2.4 Πρώτη εκτέλεση
GitHub → repo → **Actions** → *BetBot daily* → **Run workflow**.
Η πρώτη φορά κρατάει **~1 ώρα** (κατεβάζει ~60 μέρες στατιστικά από Sofascore + 1.5 χρόνο αποτελέσματα).
Οι επόμενες: 3–10 λεπτά.

### 2.5 Πού βλέπω τη σελίδα
- **Email** (αν το ρύθμισες) → συνημμένο αρχείο.
- **Από το repo**: φάκελος `docs/` → `index.html` → *Download raw* → άνοιγμα.
- **Ως site (GitHub Pages)**: Settings → Pages → Branch `main`, φάκελος `/docs`.
  ⚠️ Στο δωρεάν GitHub, το Pages δουλεύει μόνο αν το repo είναι **Public** (τότε η σελίδα είναι ορατή σε όποιον έχει το link).
  Αν το θέλεις ιδιωτικό, μείνε στο email.

## 5. Τα μοντέλα (απλά)

- **Γκολ:** κάθε ομάδα έχει «δύναμη επίθεσης» και «δύναμη άμυνας» από τα τελευταία ~1.5 χρόνια
  (τα πρόσφατα μετράνε περισσότερο). Από εκεί αναμενόμενα γκολ → πιθανότητα για κάθε σκορ → 1Χ2, Over/Under, GG.
- **Κόρνερ / κάρτες / πλάγια:** για κάθε ομάδα πόσα κάνει και πόσα δέχεται σε σχέση με τον μέσο όρο της λίγκας.
  Στις κάρτες πολλαπλασιάζεται με τον **συντελεστή διαιτητή**. Μετράμε **κίτρινες** (τα πρακτορεία μερικές φορές μετράνε την κόκκινη ως 2 – δες τους όρους).
- **Παίκτες:** ρυθμός ανά 90' στα τελευταία 10 ματς × αναμενόμενα λεπτά.
- **Μπάσκετ:** ratings επίθεσης/άμυνας ανά ομάδα + έδρα.
- **Blend με την αγορά:** η τελική πιθανότητα είναι μισή από το μοντέλο και μισή από την αγορά (`market_blend: 0.5`).
  Οι αγορές είναι πολύ ακριβείς· έτσι το bot δεν «ξεφεύγει».
- **Value** = πιθανότητα × απόδοση − 1. Θετικό = αξίζει (κατά την εκτίμησή μας).
- **«Δίκαιη απόδοση» / «παίξ' το αν ≥»:** όπου δεν βρήκαμε απόδοση (συχνά σε κόρνερ/κάρτες/πλάγια/παίκτες),
  δίνουμε την απόδοση που θα έπρεπε να έχει + 5% περιθώριο. Αν το πρακτορείο δίνει λιγότερα, **δεν** την παίζεις.

### Δελτία
Ένας αλγόριθμος (DP) διαλέγει τον συνδυασμό με τη **μεγαλύτερη πιθανότητα να πιάσει** για το εύρος απόδοσης
της λίστας, με: το πολύ 1 επιλογή ανά αγώνα, το πολύ 3 από την ίδια διοργάνωση, ελάχιστη πιθανότητα ανά επιλογή.

## 6. Κανόνες από τα λάθη (rules.py)

Κάθε φορά που χάνουμε για λόγο που **φαινόταν από πριν**, γίνεται κανόνας. Τρέχοντες:

| # | Κανόνας | Από πού |
|---|---|---|
| 1 | Όχι «νίκη» σε ομάδα με < 1.3 β/ματς στα 5 τελευταία | Atalanta 1-1 Kairat (05/11) |
| 2 | Όχι Over/GG/νίκη όταν ομάδα έχει ≥5 απουσίες ή ≥3 στην επίθεση | Leverkusen 0-1 με 8 απουσίες (05/11) |
| 3 | Μπάσκετ: το πολύ 1 στο Προτεινόμενο· γηπεδούχος < 1.55 όχι «safe» | Efes, Hapoel, ASVEL έχασαν (05/11) |
| 4 | Παίκτες μόνο με επίσημη ενδεκάδα | Pavlidis στον πάγκο (05/11) |
| 5 | Έξω ό,τι η απόδοσή του ανέβηκε ≥ 8% | αγορά κόντρα |
| 6 | Κάθε αγώνας μία φορά ανά δελτίο | ίδια ματς σε όλα τα δελτία (05/11) |

**Προσθήκη κανόνα:** άνοιξε `betbot/rules.py` → συνάρτηση `apply()` → πρόσθεσε ένα μπλοκ με σχόλιο
`# ── Κανόνας N (ημερομηνία – τι έγινε)`. Οι αριθμοί (όρια) πάνε στο `config.yaml → rules`.

## 7. Ρυθμίσεις που ίσως θες να αλλάξεις (`config.yaml`)

| Τι | Πού |
|---|---|
| Εύρος απόδοσης κάθε λίστας | `lists → x10 / x30 / x100 / recommended` (`min_total`, `max_total`) |

| Πόσο εμπιστευόμαστε το μοντέλο vs την αγορά | `selection → market_blend` |

| Ονόματα ομάδων που δεν ταιριάζουν | `team_aliases` (π.χ. `olympiakos: olympiacos`) |

| Email δεν έρχεται | Λάθος App Password / 2-βημάτων κλειστό | §2.3· στο log θα δεις `Email απέτυχε: ...` |

## 10. Συντήρηση – τι να κοιτάς

- **Κάθε εβδομάδα:** καρτέλα 📊 Ιστορικό. Ποια λίστα είναι θετική; Ποια «Επιτυχία επιλογών» είναι χαμηλότερη από την εκτιμώμενη πιθανότητα; (αν το μοντέλο λέει 70% και βγαίνει 55%, κάτι δεν πάει καλά σε αυτή την αγορά).
- **Μετά από κάθε χαμένο Προτεινόμενο:** φαινόταν από πριν; Αν ναι → νέος κανόνας (§6).
- **Κάθε μήνα:** ⚙️ Πηγές – δουλεύουν όλες; credits Odds API;
- **Νέα σεζόν (Αύγουστος):** τίποτα· το Euroleague αλλάζει σεζόν αυτόματα. Αν προστεθούν ομάδες με άλλα ονόματα, aliases.

### Τι ΔΕΝ είναι επιβεβαιωμένο (έλεγξέ το στην πρώτη πραγματική εκτέλεση)
1. **Sofascore endpoints και πεδία:** `/sport/football/scheduled-events/{date}`, `/event/{id}`, `/event/{id}/statistics` (κλειδιά `cornerKicks`, `yellowCards`, `fouls`, `throwIns`, `totalShotsOnGoal`, `shotsOnGoal`, `ballPossession`), `/event/{id}/lineups` (`confirmed`, `players[].statistics`, `missingPlayers[]` με `type`/`reason`), `/event/{id}/incidents`, `/event/{id}/odds/1/all` (`marketName`, `choiceGroup`, `choices[].fractionalValue/initialFractionalValue`).
   Τα ονόματα των αγορών αποδόσεων (`"Full time"`, `"Match goals"`, `"Both teams to score"`, `"Double chance"`, κόρνερ/κάρτες) είναι εκτίμηση: δες `_map_market()`.
2. **Ids διοργανώσεων Sofascore** στο `config.yaml` (17, 8, 23, 35, 34, 185, 7, 679, 17015). Υπάρχει εφεδρικό ταίριασμα με το όνομα.
3. **Αν το Sofascore μπλοκάρει τις IP του GitHub Actions** (403). Αν ναι, εναλλακτική είναι να τρέχει από τον υπολογιστή του χρήστη (Windows Task Scheduler). **Μην** προσθέσεις παράκαμψη προστασίας (impersonation, captcha κ.λπ.).
4. **ESPN summary πεδία** (`boxscore.teams[].statistics[].name`, `rosters[].roster[].stats`, `gameInfo.officials`): οι εναλλακτικές βρίσκονται στο `TEAM_ALT`/`PLAYER_ALT` του `espn_stats.py`.
5. **Ονόματα ομάδων ανάμεσα στις πηγές** (fuzzy matching στο `util.match_fixture`, όριο 0.62): έλεγξε ότι τα ματς από ESPN, Sofascore, fdco και Odds API ενώνονται σε ένα `match_id` και δεν δημιουργούνται διπλά. Μπορεί να χρειαστούν νέα `team_aliases`.
